how-to/firmware

Firmware handoff

Delivered and tested

firmware/src/scope_core.c is portable C for ADC-to-voltage conversion, measured two-point calibration, logarithmic TIME mapping, RANGE decoding with debounce, and bounded multiresolution min/max history. python3 scripts/test_firmware.py compiles and runs it on the host with warnings treated as errors. These tests exercise mathematics and data handling; they do not prove RP2040 operation.

firmware/src/pico_diagnostic.c initializes the specified pins, scans the three mux outputs with conservative delays, and writes raw CSV values over USB serial. It deliberately leaves the LCD off and does not implement the ten-channel high-rate engine. No prebuilt UF2 is supplied because target compilation and hardware execution were unavailable.

Local target build

Install a reviewed Pico SDK and an ARM compiler in your usual local toolchain. Set PICO_SDK_PATH to the checkout. The package does not run an unpinned SDK download during CMake configure.

cmake -S firmware -B firmware/build -DPICO_BOARD=pico
cmake --build firmware/build

The above builds only scope10_diagnostic, after local source/toolchain review. Record compiler/SDK versions and build hashes. Do not flash/energize the assembled module interface before G01 power/pin checks.

LCD integration remains open

Download the vendor example archive from the source manifest. Its module uses an SPI-to-parallel bridge around ILI9488; this is not necessarily the same transfer framing as a raw ILI9488 SPI panel. Adapt the exact 3.5-inch vendor driver to the GPIO table and disable touch/SD access. Confirm reset, CS, DC, RGB565 byte order, orientation, address-window writes and backlight behavior using color bars and corner markers before waveform drawing.

display_port.h specifies the renderer's small-rectangle API. There is intentionally no no-op fake backend: an application using these calls cannot link until a real implementation is supplied. Do not allocate a 307,200-byte framebuffer or use a generic driver with an assumed RGB666 pixel protocol.

Calibration and data provenance

firmware/tools/calibrate.py measured.csv calibration.json requires two measured DC points for every channel. Input columns are channel,volts,mean_code. Use the actual DMM-measured fixture voltage; do not pass an assumed front-panel generator setting as ground truth. Inspect intermediate 0, ±3, ±5 and ±8 V residuals after fitting. Store board serial, date, fixture identity, temperature, firmware hash and source CSV with the calibration file.

Persistent flash storage, CRC/versioning, safe defaults, a real-time display renderer, trigger alignment, DMA/PIO acquisition and hardware tests are not complete. They have explicit acceptance tasks rather than success claims. Never perform automatic “zero at startup” on attached signals.

Pre-layout evidence. No factory approval or hardware measurements are implied.
