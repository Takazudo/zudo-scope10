Local zudo-doc integration

Two usable reading paths

The offline catalogue and simulator need only Python's local HTTP server. The doc/ source also targets the native zudo-doc framework used by the lamp project: one config, package-owned route stubs and MDX content. It is not a clone of the lamp's full component validation framework.

The lamp's key principle is retained: structured component data are authoritative; pages are a generated projection. Edit catalog/components.json, source records or narrative inputs, then run python3 scripts/build_docs.py. Do not edit the generated component pages independently.

Official scaffold route

The included scripts/bootstrap_doc.sh NEW_DIRECTORY invokes the published create-zudo-doc@5.27.0 scaffold in an empty directory, copies this package's MDX, public assets and minimal config into it, and leaves dependency installation to you. It does not modify your existing lamp project or a pre-existing target directory.

bash scripts/bootstrap_doc.sh /path/to/new/scope-doc
cd /path/to/new/scope-doc
pnpm install
pnpm build
pnpm dev

The framework package/build tool were not installed or built in this environment because network package downloads were unavailable. Native build and interaction checks remain local tasks; the separate offline site is already generated.

For an existing zudo-doc workspace copy doc/src/content/docs/, doc/public/ and the selected configuration fields, resolving category collisions deliberately. Keep public source binaries under review: manufacturer files are retained for local engineering reference and do not automatically carry permission for unrestricted republication.

Component evidence

Each generated record carries exact or unresolved identity, role, package candidate, pin mapping, source links, retained file hashes, source availability and separate open questions. A verified part identity does not mean a verified footprint, a verified factory process, an assembled board or a successful measurement. Blank asset sections say explicitly that a model or datasheet was not recovered.

The pot has an original downloaded manufacturer STEP and drawing files recovered from the earlier component ZIP. The Pico/display STEP files were not downloaded successfully; the mechanical envelope study is not substituted for exact CAD. Missing binary downloads are listed and a local source-fetch script is supplied.

Pre-layout evidence. No factory approval or hardware measurements are implied.
